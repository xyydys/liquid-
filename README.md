# LiquidGlassLab 0.4.0：抖音首页结构实验（完整工程）

这是可以直接编译的完整工程：Theos 应用工程，加上 GitHub Actions 云编译，产出 IPA 和 rootless deb。

## 工程结构

| 文件 | 作用 |
|---|---|
| `Makefile` | Theos 应用工程：arm64，最低 iOS 26.0，Swift 用 `-swift-version 5` |
| `main.m`、`AppDelegate.h/.m` | App 入口 |
| `SceneDelegate.h/.m` | 建窗口，调用 Swift 的 `+[LiquidGlassRootFactory makeRootViewController]` |
| `LiquidGlassLabRoot.swift` | 全部实验界面（底栏、首页、顶部分组、左右按钮、右侧按钮列、实验设置） |
| `Resources/Info.plist`、`Resources/AppIcon60x60@2x/@3x.png` | App 信息和图标 |
| `control` | deb 包信息 |
| `.github/workflows/build.yml` | 云编译 |
| `scripts/package_ipa.sh` | 把编好的 App 打成 IPA |
| `push_to_github.sh` | 手机上一键推送 |

## 编译

### 云编译

在手机上运行：

```
cd /var/mobile && unzip -oq LiquidGlassLab_0.4.0_full_project.zip -d LiquidGlassLab_0.4.0 && cd LiquidGlassLab_0.4.0 && bash push_to_github.sh
```

`push_to_github.sh` 会把整个工程推到 `lu8389772-cloud/AwemeAlbumMorphBar-SwiftUI26` 的 **`liquidglasslab` 分支**。这个分支是单独的，不带 main 的历史，main 上的旧插件代码完全不动。

推送后，GitHub Actions 依次执行：

1. 先用 iPhone SDK 对 Swift 做类型检查；
2. 对入口的 ObjC 文件做语法检查；
3. 用 Theos 编译；
4. 打出 IPA。

结果在 Actions 里，产物名是 `LiquidGlassLab-0.4.0`，里面有：

- `LiquidGlassLab-0.4.0.ipa`：用 ldid 伪签名，侧载工具可以重签；
- `com.xyy.liquidglasslab_0.4.0_iphoneos-arm64.deb`：rootless。

如果本地旧目录 `/var/mobile/AwemeAlbumMorphBar-SwiftUI26` 的 origin 就是这个仓库（比如已经配好的 SSH 地址），脚本会沿用它的地址；否则用 HTTPS 地址，推送时按提示输入账号和令牌。也可以用环境变量 `LAB_REMOTE_URL=... bash push_to_github.sh` 指定别的仓库。

### 本地编译

在有 Theos 和 iOS 26 以上 SDK 的环境里，运行 `make package`，再运行 `bash scripts/package_ipa.sh`。

## 这一版的内容

0.4.0 在 0.3.4 已验证的原生底栏基础上，把第一个标签换成“首页”。首页是一个竖向翻页的假视频流，上面叠着：

- 顶部分组；
- 分组左右两个按钮：左边是菜单，右边是搜索；
- 右侧按钮列：头像、点赞、评论、收藏、分享、音乐。

这些都可以缩放和切换实现方式。目的是先在这个 App 里把它们做对，再把确认过的结构和状态搬进插件。

## 不变的部分

- `UITabBarController`、四个普通标签加系统搜索标签、`tabBarMinimizeBehavior = .onScrollDown`。设置里可以关掉最小化。
- 精选集、相簿、共享、搜索四个标签页与 0.3.4 完全相同。
- 仍然没有 `bottomAccessory`。底栏的材质、选中胶囊和缩小动画全部由 UIKit 负责。

## 首页

- **视频流**：80 页渐变背景，亮色和暗色交替，方便对照玻璃在亮背景和暗背景上的样子。它是底栏的内容滚动视图，下翻时底栏会照常缩小。
- **打开实验设置**：长按画面，或点左上角菜单 → “实验设置”。设置面板有小、中、大三档高度，停在小档或中档时可以继续操作首页，所有改动即时生效。

### 顶部分组（分组实现）

| 选项 | 结构 | 用途 |
|---|---|---|
| 独立标签栏 | 自己持有的 `UITabBar` | 不经过控制器，可以在只有一个分类时去掉选中胶囊 |
| 标签栏控制器 | 子 `UITabBarController`，与插件 2.5 相同 | 用来对照插件现在的结构，看背景色块、形状和边距是否来自控制器 |
| 导航栏按钮组 | 导航栏 `centerItemGroups`，编辑器样式 | 分组也是导航栏玻璃，左右键与它同属一条栏 |

- **原生尺寸**：前两种由 UIKit 按原生尺寸绘制胶囊、文字项和选中透镜。程序先找到 UIKit 自己的胶囊视图，再调整整条栏的宽度，使胶囊正好等于“分组单项宽度 × 项数”。
- **分组比例**：整条栏整体缩放。文字图片按同一比例放大绘制，并使用对应的像素密度，缩放后仍然清晰。
- **分组数量**：1 到 4。只有 1 个时，可以左右滑动切换分类。
- **超出可见范围的分类**：点最边上的分类后，可见窗口会移动一格，与插件的行为一致。

### 分组左右按钮（按钮实现）

| 选项 | 结构 |
|---|---|
| 导航栏 | 系统导航栏的左右按钮，属于栏玻璃，与底栏同一类，带原生菜单展开和按压形变 |
| 按钮R / 按钮C | `UIButton.Configuration.glass()` / `.clearGlass()` |
| 视图R / 视图C | 交互式 `UIGlassEffect` 视图里放一个普通按钮。这种结构与插件的承载视图类似 |

- **按钮比例**：导航栏方式是整条栏缩放，栏宽同时放大到 1/比例，所以缩放后仍然铺满屏幕。玻璃按钮和玻璃视图按真实尺寸重建，不使用缩放变换。
- **按钮边距**：导航栏方式通过 `directionalLayoutMargins` 设置。
- **按钮靠近分组**：只对玻璃按钮和玻璃视图有效。
- **左键菜单**：内容是全部分类加“实验设置”，每次打开时重新生成，所以勾选状态始终跟随分组，按钮本身不会被替换。

### 顶部背景

- **顶部边缘效果**：可选隐藏、自动、软、硬。除“隐藏”外，会把整个顶栏登记为视频流顶部的边缘元素（`UIScrollEdgeElementContainerInteraction`），由系统在后面画一整块效果。
- **栏使用透明外观**：只作为对照，插件不建议使用，因为它会让栏换用另一套表面配方。

### 右侧按钮

- **材质**：四选一，与左右按钮的四种相同。
- **整体缩放**：按真实尺寸缩放，即直径和图标字号一起变，不使用缩放变换。
- **其他**：间距、右边距、距底栏的高度都可以调。
- **点赞**：可以切换，点赞后变红，计数加一。

### 测量信息

设置面板最上方会列出：

- 屏幕和安全区；
- 导航栏的原生尺寸和每个栏按钮在屏幕上的位置；
- 分组的原生胶囊尺寸、画布尺寸、比例和屏幕位置；
- 左右圆钮的位置；
- 右侧按钮列的位置和直径。

“复制测量信息”会把这些内容复制到剪贴板。找到满意的组合后发回这段文字，就能把同样的数字搬进插件。

### 崩溃自恢复

设置会保存下来。如果某个组合在重建顶栏时让 App 闪退，下次启动会自动恢复默认设置，不会每次一打开就闪退。

## 建议对照的几个问题（对应插件 2.5.3 的反馈）

1. **一个分类时形状和边距**：分组数量设为 1，分别看“独立标签栏”和“标签栏控制器”两种方式下胶囊的形状、左右留白，以及有没有选中胶囊。
2. **顶部三块背景**：切换三种分组实现，再在“顶部边缘效果”的四档之间切换，看哪一种会出现分块的背景。
3. **回到前台时左键“刷新”**：打开控制中心、回桌面再回来、打开设置后返回，看导航栏按钮和玻璃按钮有没有闪一下。
4. **按压拉伸形变**：分别按住导航栏按钮、玻璃按钮、玻璃视图并拖动，对比哪一种有系统按钮那种拉伸和扭曲。
5. **材质是否一致**：对照左右按钮与底栏未选中区域的颜色，尤其是导航栏方式和标签栏两种方式。
